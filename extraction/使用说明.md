# 使用说明 — 识别 · 审核 · 对账 · 总账 · 报表 · 对手方 · 学习规则

> 给第一次用的人。四句话看懂：**① 上传发票或银行流水 → 自动识别；② 在审核页对照原件核对/改错；③ 银行流水可到「对账确认」页自动和发票配对，高可信的一键批量通过、异常才逐笔看；④ 系统在你核对时"学"规律，你确认启用后以后更准。** 审核通过的发票可到「总账」页由你**点一下入账**（生成借贷平衡的会计分录、看试算平衡）。
> 两条铁律：**系统绝不自动入账**（一切以你"通过/确认"为准）；**学到的规则默认不生效，要你点"启用"才用**。

---

## 一、整体流程

```
              ┌── 发票 ──▶ 自动识别 ──▶ 发票审核（核对/改错/通过）───────────────┐
上传（可选类型）                                                                 ├─▶ 导出 / 入账
              └── 银行流水 ──▶ 自动识别（多格式）──▶ 流水审核 ──▶ 对账确认 ──────┘
                                                          （发票↔流水自动匹配→批量确认/例外处理）
```

七个页面：**上传页**、**人工审核页**（`/review`，发票与流水分开）、**对账确认页**（`/reconcile`）、**总账页**（`/ledger`）、**财务报表页**（`/reports`）、**对手方页**（`/counterparties`）、**已学规则页**（`/learned`）。**每页顶部都有同一条固定导航栏**，列出全部模块并高亮当前所在页，随时一键切换（和普通网站一样）。

## 二、上传与识别（上传页）

1. 顶部先选 **「📄 发票」还是「🏦 银行流水」**，再把文件**拖进虚线框**（或点击选择），可一次多传。
2. **发票**几乎什么常见格式都能传：
   - **PDF**（电子版 / 扫描件都行，扫描件走 OCR）；
   - **Word**：`.docx` 及旧版 `.doc`、以及 `.rtf` / `.odt`（自动转换后识别，表格逐格读）；
   - **Excel**：`.xlsx` 及旧版 `.xls`、`.ods`（读全部单元格、不会因列窄被截断）；
   - **图片**：`jpg / png / tiff / bmp / webp / gif`（走 OCR）。
   旧/少见格式会**自动转换**后再识别，无需你先另存。
3. **各种数字/币种写法都认**：美式 `1,234.56`、欧式 `1.234,56`、空格千分位 `1 234,56`；货币符号或代码在前在后都行（`$1,900`、`HK$1,200`、`1,900.00 USD`、`€ 1.234,56`）；含税价、折扣/运费行、贷记单负数等也能正确归位。中英文发票、香港/欧美/中国增值税等常见版面都覆盖。
4. **银行流水**支持很多格式：**CSV / TSV / Excel / PDF / 图片**，以及银行导出的 **OFX / QFX / MT940 / CAMT.053(XML) / QIF / 定宽文本** 等——结构化格式直接精确解析，最可靠。
5. 上传后**自动识别**，进入对应审核队列（发票、流水各一份，互不混）。**识别失败的也会入库**（不丢），标"⚠ 提取失败"，可对照原件手工录入。
6. 一个文件含**多张发票**（发票号各不相同）会自动拆成一张一条；**一张发票带明细附表/跨页续页（重复同一发票号）不会被误拆成多张**。拆得不对可在审核页「合并回单张 / 重新切分 / 人工画线重切」调整。
7. **「🏦 最近识别的流水交易」卡片**（仅在顶部选中「🏦 银行流水」时显示；选「📄 发票」时不显示）：上传银行流水后，这里以小表格实时列出**最近成功识别的 10 笔交易**（按最新上传的流水排序，显示日期/摘要/收入/支出/余额/来源）。**点任一行**即可跳进该流水的审核详情、并**直接定位到这一笔交易**——识别出来的那一行与原件里对应的那一行都会**闪动几下**，方便快速找到、核对。没有已识别流水时该卡片自动隐藏。
8. 导出（**核对通过后再用**）：「导出全部」/「仅导出已通过」（推荐——把"审核通过"当入账闸门）。

## 三、发票人工审核（`/review` → 📄 审核发票）

**布局**：左=待审队列；打开一条后 **左半屏=发票原件、右半屏=识别字段**。

- **点字段 ↔ 点原件蓝框**：双向高亮，快速定位这个值在原件哪里。
- **改值**：直接改输入框，**失焦即保存**、自动留痕（改前/改后/人/时间）。金额/日期/币种自动规范化；对不平/待复核会**标红**。
- **框选原件**一段文字 → 填进某字段 或 加一条明细。
- **服务明细**：可改描述/数量/单价/金额；有勾稽子明细会显示"是否对得上"。
- **多张发票（合集）**：同一文件的多张折叠成一组（📎），每张顶部有纠正按钮：「合并回单张」/「重新切分」/「人工画线重切」（在每张开头点一条横线）。
- **用最新规则重新识别**：改了逻辑/启用了新规则后旧记录不自动变——单条点「↻ 按最新规则重新提取」，或队列上方「↻ 全部未通过…」（可选范围：全部发票/全部流水/两者）。**保留你手改过的字段**，已通过的跳过。⚠ 浏览器"刷新"≠重新识别。
- **完成**：每条下方 ✓通过 / 待定 / ✗拒绝(填原因) / 🗑删除；通过前做关键字段/勾稽校验；可勾选**批量通过**；快捷键 `j/k` 上下、`a` 通过并下一条、`r` 拒绝、`h` 待定、`?` 帮助。
- **需纠错的排最前 + 一眼看清要改哪**：未通过提取校验（缺必填/勾稽不平/重复/金额存疑/提取失败等，暂不参与对账）的记录自动排到队列最前、标「⚠ 需纠错」；打开后**详情顶部橙框会逐条列出"必须先修正才能参与对账匹配"的具体项**，缺字段的可**点一下直接跳到该字段填写**。（下方"校验问题"里其余提示不阻断匹配。）
- **回到上次位置**：刷新或重进后，会停在你上次在看的那条、上次的标签。

## 四、银行流水审核（`/review` → 🏦 审核流水）

- 顶部切到「🏦 审核流水」，只看流水清单（不混发票）。
- 右侧是**账户信息 + 逐笔交易表**（日期/摘要/收入/支出/余额），可逐笔核对、直接改，摘要长会自动换行显示全。
- 左侧原件有两种视图，可切换：
  - **🔍 整理视图**：把交易排成规范表，**点某笔交易 → 左侧对应行高亮**（日期绿、金额橙、发票号蓝），方便对照；
  - **📄 原件**：显示**源文件真实字节**（完整、不截断），可**「适应」宽度自适应 + `+/−` 缩放**，用来核对系统提取得对不对。
- **金额方向**：支出/收入分列显示；对账证据里用 `OUT/IN` 标方向（银行原文里付款常是负数，属正常）。
- 走完对账后（见下）：**已对账的交易**会标 **🔒已对账**、锁定不可改；流水显示**「已对账 X/N」**进度；**当一条流水的交易全部对账后，自动从待审队列移出**。未对账的交易（如手续费）仍可正常编辑。

## 五、对账确认（`/reconcile`）——发票 ↔ 银行流水 自动匹配

> 目的：**自动匹配为主、人工只处理例外**。别再逐笔翻。

1. 点 **「▶ 运行自动匹配」**：系统把通过校验的发票和流水交易自动配对。（未通过提取校验的会**横幅提示**先去审核页纠错——**点横幅直接跳到审核页、自动定位到第一条待纠错记录**，待纠错的也会被排到审核队列最前、标「⚠ 需纠错」。）
2. 结果按**置信度/风险**分到几个标签：
   - **待批量确认**：高可信且唯一 → 「✓ 一键全部通过」；
   - **待确认**：中等可信 / 一票多付 / 多票合并付 / 有差额（手续费·外币）→ 逐组确认；
   - **多候选/重点审核**：一笔有多个像的候选，要你判断；
   - **未匹配/待补证**：需要发票却还没配上（如"供应商付款·待采购发票"）；
   - **无需匹配(待核)**：手续费/工资/税款/内部划转/借还款/押金预付等**本就不需要发票**的（系统先识别交易类型再决定要不要发票）。核对后点「✓ 确认无需发票」即标为已处理（该交易锁定、从流水待办里减去、整条流水处理完会自动移出审核队列）；点错可在「已确认」里「↩ 撤销」。
   - **已确认**：已核对入账的。
3. **「🔍 展开对照」**：点开一组，左看**发票原件**、右看**对应流水**（① 原件源文件节选可独立核对 + ② 系统提取）。四要素**统一分色框出**：**蓝=发票号、绿=日期、橙=金额、紫=公司/供应商**，两侧同色，一眼看清"是不是同一家、同一单"。
4. 每组「✓ 确认对应关系 / ✗ 不成立」；确认后自动跳到下一条；刷新后回到上次位置。
5. **确认错了可反做**：到「已确认」标签，对已对账的那组点「↩ 撤销对账」——退回待确认，并**解锁**对应发票/流水(之后可再改/删或重新对账)，动作留痕。（发票若已「通过」也可在审核页点「待定/拒绝」退回后再改删。）

**几条重要保障（防错防漏）**：
- **未匹配 ≠ 异常**：非采购/销售类的流水本就无需发票，不会被当异常。但为**防误判漏票**：只有"类型明确 + 小额 + 不含单据号"才自动归「无需匹配」；**大额、含发票号/单据号、类型不确定的一律不自动跳过**，进「待确认」让你核。
- **发票后到会自动重配**：进了「未匹配」或「无需匹配」的交易**不锁定**；发票晚到后再点一次「运行自动匹配」就会自动配上。
- **不会重复对账**：一张发票、一笔流水只能对账入账一处；已确认的不会被再次对应、也不能被随意改删——**要改先在「已确认」里点「↩ 撤销对账」**反做（会解锁并留痕），不是永久锁死。
- **确认≠系统自动记账**：确认只是"确认对应关系并核对入账"，仍是你人工把关。

## 六、总账入账（`/ledger` 页）——审核通过的发票 → 会计分录

> **系统绝不自动入账**：只有你在这页点「确认入账」，才把一张**已审核通过**的发票过账成一张借贷平衡的会计分录。

页面顶部五个视图（点标签切换）：

- **待入账**：列出所有已审核通过、但还没入账的发票，每张都给一份**建议分录预览**（借哪个科目、贷哪个科目、各多少）。
  - **方向**：默认「应付/费用（AP）」= 你收到的账单（记成本/费用 + 应付账款）；若这张是你**开给客户**的发票，把方向切成「应收/收入（AR）」。核对无误点「**✓ 确认入账（过账）**」，系统给出**凭证号**（形如 `202606-0001`）。
  - **权责发生制**：发票入账只挂**应付/应收**、不直接动银行；实际收/付款时到「待结算」做资金结算。
- **待结算**：列出所有已入账、但还有未结余额的发票（显示全额/已结/未结）。到实际收/付款时，填「清账票面额」（默认全部未结）+「实收/付现金」+ 选「差额原因」，点「**✓ 结算**」。
  - **差额原因**（票面额和实际现金不一致时选）：手续费（银行/平台扣的）、预扣税（收/付款被代扣的）、现金折扣、舍入差异（几分钱的微差）。系统据此把差额自动记进正确科目、方向也自动定；**没有差额就选「无差额」**。
  - **不自动凑平**：如果有差额又没选原因科目，系统会**拒绝结算**并提示——绝不悄悄把账做平。可**分次部分结算**、也可一笔钱结多张票。
  - 顶部会显示**应付/应收总账余额是否等于各票未结之和**（对账一致性），不一致会红字告警。
- **新建凭证**（手工记账凭证）：发票之外的账也能记——**期初建账、计提/摊销/折旧、调整纠错、没有发票的银行手续费/利息**都用它。
  - 填**记账日期** + **凭证摘要**，然后逐行选科目（可下拉选，也可手填表外但编码合规的科目）、填**借或贷其中一边**、可写行摘要；「+ 加一行」可加更多行。
  - **手填科目请以编码开头**（如 `6440 会计费`）。编码贴着名字写（`6440会计费`）也认得，系统会自动整理成科目表里的标准名称，
    保证同一个科目不会在账上分裂成两行。
  - 底部实时显示**借合计 / 贷合计**与是否平；**不平就不让过账**（按钮是灰的）。
  - 有银行/现金的行时，必须选**现金流活动**（经营/投资/筹资）——这样现金流量表才能自动归类。
  - 用到**应付账款 / 应收账款**时会弹出橙色提示：这两个科目正常应由发票入账/结算产生，手工动它要**勾选确认**（确认是期初建账或往来调整）并**填对手方**，否则不让过账。填了对手方，这笔往来才能被追踪、也不会让上面的"总账余额 = 各票未结之和"误报不一致。
- **已过账分录**：所有入账/结算后的分录，逐张显示借贷明细。做错了点「**↩ 红冲**」——生成一张方向相反的冲销分录（原分录不删、标"已红冲"，符合会计规范），可追溯。
- **试算平衡**：所有科目的借方/贷方合计。**借贷总额必须相等**（系统强制每张分录借贷平衡，不平不让入账），底部显示合计与「平衡 ✓」。
  - 顶部若出现橙字「**N 张历史分录动了现金但没标现金流活动**」：这是早期版本留下的记录（当时漏判了现金科目），
    会导致现金流量表少算、报表勾稽通不过。到「已过账分录」找到这些凭证，点「↩ 红冲」后**重新录一遍并选上现金流活动**即可。
  - 下方还有**期末关账**面板：列出各会计期间与状态。点「🔒 关账并结转」会把该期损益结转进未分配利润并**锁定该期**（之后不能再往这个月过账，显示结转出来的净利润）；发现要补账就点「↩ 重开」（自动红冲结转、解锁）。**关账也是人工动作，系统不会自己关。**

**几条保障**：**未审核通过的发票不能入账**（先去审核页「通过」）；**同一张发票不会重复入账**（已入账再点会被拒）；结算**不能超过未结额**；**金额用高精度十进制**（不会有小数误差）。

## 七、对手方建档（`/counterparties` 页）——供应商 / 客户主数据

> 目的：让同一家公司只有**一个身份**。发票上"ACME"、"ACME Inc."、"Acme, Inc" 其实是一家，若不建档，往来账和供应商汇总会散成好几家。**系统不会自动建档、也不会自动合并**，只帮你找出可能是同一家的候选。

两个视图：

- **待建档**：发票上出现过、但还没建档的对手方。每条显示**出现次数**、来自哪些发票，以及**相似的已建档对手方**（标出相似度、疑似同一家的会高亮）。
  - 是同一家 → 点「**↳ 并入此对手方**」，这个写法就记成它的**别名**，以后同样写法自动认得。
  - 是新的一家 → 填**规范名**（正式写法，可改）、选**类型**（供应商/客户/两者/**本方主体**）、可填税号和备注，点「**✓ 建档为新对手方**」。若和已有的太像，系统会先拦一下，确认"确实是另一家"后才建。
  - **发票上的"客户"经常就是你自己公司**：把它建档为类型「**本方主体（我方公司）**」，之后就不会再出现在这里。
- **已建档**：全部对手方，可改类型、税号、备注，可**加别名**（把发票上的其他写法归进来），可**停用**（只归档、不删历史）。
  - **名称不在这里改**：要改名请新建档、再把旧写法记成别名，保证历史可追溯。

**和总账的关系**：手工凭证里动应付/应收要填对手方，建议就填这里的规范名。

## 八、学习规则（`/learned` 页）

> 系统在你审核时**悄悄"学"规律**（纯本地、不用 AI 大模型），但**默认不生效**，要你在这页点「启用」才用。发票、流水各有一份规则清单（顶部可切）。

- 学的几类：**分类科目 / 字段默认值 / 字段定位线索 / 明细拆分 / 单张多张**——每条都有大白话说明"启用后会做什么"。
- 用法：看到合适的点「**启用**」，按钮上写明范围（「只用这家开票方」更稳 / 「所有发票通用」）；学得不准点「**✎ 修改**」当场改（上方大文本框可**一句话写规则**，点「解析这句话」自动填成规则）；不要的「删除」。
- 状态：`待确认`=学到还没生效；`已启用`=在用。规则**只影响启用之后新上传/重新提取的**，旧记录要去审核页「按最新规则重新提取」。

## 九、财务报表（`/reports` 页）——利润表 + 资产负债表 + 现金流量表

> 从总账已入账的分录**自动生成**三张报表，不用手工填。**勾稽通过才出表**（系统自动校验"资产 = 负债 + 权益"、"现金流量表期末现金 = 货币资金"、科目都归了类）。

- **利润表**：营业收入 − 成本费用 = 净利润（本期）。
- **资产负债表**：资产、负债、权益三段；底部校验"资产 = 负债 + 权益"，右上角标「✓ 平衡」。本期净利润会自动并入权益。
- **现金流量表（直接法）**：按经营 / 投资 / 筹资三类活动汇总现金流入流出、算出现金净增加与期末现金。每笔现金活动的类别在**结算时**就打好（默认按发票性质：买固定资产=投资、日常费用/收入=经营，可在结算时手动改）。右上角校验"期末现金 = 资产负债表货币资金"。
- 页面顶部有一条**勾稽横幅**：绿色=通过、可出表（右侧有「⬇ 导出 Excel」按钮）；红色=未通过（科目没归类 / 不平衡 / 现金对不上），此时下方只当草稿看、并列出差异帮你定位、**不给导出**。
- **导出 Excel**：勾稽通过时点「⬇ 导出 Excel」下载工作簿，含 7 页——封面、三张报表、勾稽校验，外加**科目余额（取数轨迹）**与**分录明细（凭证轨迹）**两页，报表每个数字都能顺着这两页往下查到科目、查到分录。
- 口径：IFRS、功能货币 USD、单期（本期累计）。**负数标红**。
- **后续增量**：现金流量表间接法交叉验证、PDF 导出、跨期对比暂未做。

## 十、常见疑问

- **改了半天怎么没变？** 浏览器刷新只显示旧结果、不重跑识别；要「按最新规则重新提取」或重新上传。
- **会自动记账吗？** 不会。系统只识别+匹配+建议，一切以你"通过/确认"为准。
- **流水提取出来金额是负的？** 那是 OFX/QFX 等格式**原文用带符号金额**（负=付款）；系统内部按"支出/收入"正数分列，证据卡用 `OUT/IN` 标方向，不影响对账。
- **进了"无需匹配"，后来发票到了怎么办？** 不会漏——它不锁定，重跑一次「运行自动匹配」就会自动配上。
- **已对账的流水还在审核队列吗？** 部分对账的会显示「已对账 X/N」并锁住已对账那几笔；全部对账后自动移出待审队列。
- **识别失败/字段空？** 不丢件——入库标"提取失败"，对照左侧原件手工填。
- **多张发票拆错了？** 用发票顶部"合并回单张 / 重新切分 / 人工画线重切"。
- **数据安全**：全部本地/内网、不上公有云、不用云端 AI；演示站是隔离沙盒，**请勿录入真实数据**。
